# Аудит копирования mo-money

Целевой адрес в конфигурации `0x32ed2e546b187ca15e2841edc82b22c713cf8ec3`
соответствует [профилю mo-money](https://www.polyfollow.com/traders/0x32ed2e546b187ca15e2841edc82b22c713cf8ec3).
Это PAPER-симулятор, не исполнитель реальных ордеров. Проверены исходный код,
локальные тесты и публичная документация API, но не сам запущенный экземпляр
и не реальные ответы Polymarket из этой среды.

## Исправлено

- API v2: корректный параметр `taker_only=false` (maker и taker); продолжение
  чтения после пустой страницы с курсором; неверный формат не считается пустой
  успешной лентой; обнаружение зацикленного курсора.
- Начальная граница наблюдения сохраняется до первого сетевого запроса, чтобы
  старые события с поздних страниц не принимались за новые. Очередь продолжает
  исполняться при временной недоступности обеих лент.
- Очередь и состояние до исполнения записываются вместе; результат, подробные
  строки истории и соответствующий снимок счёта сохраняются в одной транзакции.
  При ошибке SQLite состояние восстанавливается из последнего снимка.
- Одна порция ликвидности в кешированном стакане не используется повторно в
  течение срока жизни снимка. Отвергаются некорректные значения цен и размеров.
- Корректный SELL при нехватке наличных на комиссию, если выручка её покрывает;
  отказ SELL/MERGE/REDEEM по газу или комиссии не портит позиции.
- REDEEM обрабатывает только размер и исход отдельной строки с указанной
  выплатой, вместо закрытия всего рынка и угадывания победителя по нулевой
  выплате. При отсутствии размера/выплаты операция отмечается пропущенной.
  Автопогашение до события кошелька отключено для copy-режима.
- Опрос активности по умолчанию ускорен с 5 до 0,5 секунд; события сортируются
  с нормализацией миллисекунд. Это уменьшает, но не устраняет задержку и ошибки
  порядка между двумя независимыми лентами.

## Оставшиеся ограничения и риски

- Физически невозможно гарантировать полное и мгновенное копирование с той же
  ценой: публичные сделки сообщаются постфактум, новые заявки не попадают в
  очередь источника, цена и ликвидность меняются. Проскальзывание ограничено
  `COPY_MAX_SLIP`; плохой стакан, пустая позиция или недостаток денег дают
  SKIPPED/PARTIAL. Новый снимок CLOB может снова содержать ту же ликвидность,
  поскольку бумажные заявки не меняют реальный стакан.
- API trades по документации имеет минимальный фильтр 0,01 токена; публичная
  лента не доказывает полноту, возможны задержки индексации, ошибки и лимиты.
  Без уникального ID невозможно надёжно отличить одинаковые реальные исполнения
  от повторных строк. Запоздавшее событие может прийти позади уже прочитанной
  границы. Время при сбросе имеет субсекундную точность, у API — секунды:
  пограничная секунда может не попасть в копирование.
- Начальные открытые позиции кошелька не импортируются. Поэтому после чистого
  старта его продажа, MERGE или REDEEM старой позиции может не исполниться.
- Ленты trades и activity индексируются и читаются раздельно: например, SELL
  может быть замечен раньше предшествующего SPLIT. CONVERSION, награды, rebates
  и другие неподдерживаемые типы не повторяются. Исходы нестандартных рынков,
  мультивыплаты, комиссии и данные о рынке требуют сверки на реальном API.
- Статус FILLED означает лишь симулированное исполнение, а не реальную сделку.
  Теневой учёт не включает старые позиции и не является подтверждённым PnL кошелька.
- Размеры в exact округляются вниз до 0,01; сделки меньше рыночного минимума
  пропускаются, остаток не переносится. Это не строгая копия каждого количества.
- Параллельный запуск нескольких экземпляров на одной базе не поддерживается.
  Удалённая база в этой среде недоступна, она не была сброшена.
